# 단계별 검증표

## 관리 방식

실행 가능한 회귀 테스트는 루트의 `tests/`, 검증 계획은 `검증문서/테스트/`,
검증 결과는 `검증문서/테스트/실행결과/`, 실제 실행 산출물은 `outputs/{run_id}/`에 둡니다.
실제 API를 쓰는 수동 점검은 기존 `scripts/api_smoke.py`처럼 명시적으로 실행하고,
일반 pytest 실행에 유료 호출을 섞지 않습니다.

## 개별 실행 명령

저장소 루트에서 `source .venv/bin/activate` 후 실행합니다.
아래 pytest 명령은 실제 API를 호출하지 않습니다.

```bash
# 설정과 API 어댑터 계약
python -m pytest tests/test_config.py tests/test_openai_adapter.py -q
# 원문 읽기와 RAG 도구
python -m pytest tests/test_tools.py -q
# 기술/시장/이해관계자/도메인의 공통 연구 로직
python -m pytest tests/test_agents.py -k research -q
# 근거 검증
python -m pytest tests/test_agents.py -k verification -q
# 종합
python -m pytest tests/test_agents.py -k synthesis -q
# 보고서 작성
python -m pytest tests/test_agents.py -k report -q
# Supervisor, 병렬 처리, 재시도
python -m pytest tests/test_graph.py -q
# PDF와 파일 저장
python -m pytest tests/test_pdf.py tests/test_artifacts.py -q
# 실제 에이전트 코드를 대체 LLM/도구로 연결하는 통합 검사
python -m pytest tests/test_full_pipeline.py -q
```

실제 API 최소 점검은 `python scripts/api_smoke.py`입니다. 유료 호출이 발생합니다.
현재 `main.py`에는 단계 선택 실행 기능이 없으므로 위 명령을 실제 API 단계별 실행으로 해석하지 않습니다.
실제 단계별 검증을 추가할 때에는 입력 상태를 준비하는 별도 수동 실행기를 만들고,
앞 단계 산출물을 다음 단계 입력으로 재사용하도록 구성합니다.

## 결과 기록 양식

```text

구분: 고정 입력 테스트 / 데모 / 실제 API
명령 / Python 환경:
입력 파일 또는 이전 단계 run ID:
기대 결과:
실제 결과 / PASS, FAIL, 미검증:
출처 연결 및 내용 검토 결과:
증거 파일: 검증문서/테스트/실행결과/... 또는 outputs/{run_id}/...
관련 오류 ID / 수정 / 재검증:
```

`.env` 원문, API 키, 인증 헤더는 기록하지 않습니다.
