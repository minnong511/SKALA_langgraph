# 디버깅 기록

오류의 증상, 원인, 수정, 재검증 결과를 이 폴더에서 추적합니다.

- [오류 추적표](ISSUES.md): 해결 여부와 다음 조치
- [단계별 검증표](../테스트/단계별검증.md): 단계별 확인 범위, 실행 명령, 실제 API 검증 여부
- `검증문서/테스트/실행결과/`: 실행 시점별 검증 결과. API 기록의 시각과 파일명은 UTC입니다.
- `scripts/api_smoke.py`: 설정, LLM 일반 응답, 실제 ResearchOutput 스키마, Tavily 검색 확인

## 재현

저장소 루트에서 프로젝트 의존성이 설치된 Python으로 실행합니다.

```bash
python scripts/api_smoke.py
python -m pytest -q --tb=no
```

API 테스트는 실제 유료 호출을 수행합니다. LLM 2회, Tavily basic 검색 1회이며,
전체 그래프, 논문 업로드, 임베딩 생성은 실행하지 않습니다. `.env`를 내부에서 읽되
키, 설정 원문, 응답 본문, 원본 예외는 저장하지 않습니다. 각 실행마다 새로운 JSON을 남깁니다.

최초 API 검증은 기존 `sllm` 환경에서, 이후 자동 테스트는 프로젝트 `.venv`(Python 3.14.6)에서 실행했습니다.
프로젝트 선언 범위와 `.python-version`도 Python 3.14로 맞췄습니다.

## 기록 규칙

새 오류마다 `DBG-###` ID를 부여하고 증상, 원인, 수정 파일, 증거, 다음 조치를 기록합니다.
상태는 `미해결`, `수정 후 검증`, `해결`로 구분합니다. 기존 실패 기록은 보존하고
재검증 결과를 추가합니다. 성공한 API 호출을 전체 프로젝트 정상 동작으로 해석하지 않습니다.

테스트 실행 코드는 기존 `tests/`에 추가하고, 확인 기준과 결과는 이 폴더에 기록합니다.
`outputs/`는 실행 원본을 보관하며, Git에서 제외되므로 공유할 검증 결과는 비밀정보를 제외한 요약을 `검증문서/테스트/실행결과/`에 남깁니다.
